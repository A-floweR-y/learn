# 嵌套 location 匹配流程图

> 速查图。讲解和实验在 [location 匹配规则](./location.md) 的「嵌套 location」。返回 [Nginx](./README.md)。

嵌套没有新规则。每一层仍是：精确匹配最优先、前缀取最长、正则按书写顺序。层与层之间走两趟：**前缀从外往里，正则从里往外。**

```text
                      收到请求
                         │
                         ▼
═════════════ 第一步：先逐步向内找最长前缀 ═════════════

             本层有 = 精确匹配吗？
               ├─ 有 ──▶ 直接命中，整个查找结束 ✔
               └─ 没有 ─▶ 在本层挑最长前缀
                            │
                ┌───────────┴───────────┐
             没挑到                    挑到了
                │                        │
                ▼                        ▼
         父级就是最长前缀      它里面还有子 location 吗？
                │              ├─ 有 ──▶ 进入这一层，回到第一步开头
                │              └─ 没有 ─▶ 它就是最长前缀
                └───────────┬───────────┘
                            ▼
════════════════ 第二步：逐步向外找正则 ════════════════

          最长前缀里面有子 location 吗？
            ├─ 有 ──▶ 先查这些子 location 里的正则
            │           ├─ 命中 ───▶ 用这条正则 ✔（结束）
            │           └─ 没命中 ─┐
            └─ 没有 ───────────────┤
                                   ▼
                      来到最长前缀的同级那一层
                                   │
                                   ▼
          【查本层正则】这层选中的前缀带 ^~ 吗？
                       ├─ 带 ───▶ 跳过这层的正则，往外继续找 ┐
                       └─ 不带 ─▶ 按书写顺序查这层的正则     │
                                   ├─ 命中 ──▶ 用这条正则 ✔（结束）
                                   └─ 没命中 ───────────────┤
                                                         ▼
                                                 外面还有层吗？
                                                   ├─ 有 ──▶ 退到外面一层，回到【查本层正则】
                                                   └─ 没有 ─▶ 用最长前缀 ✔（结束）
```

两条提醒：

- 走进一层，就是完整的一轮匹配：先挑这一层的前缀，挑不到，才轮到这一层的正则。
- `^~` 只跳过**当前这一层**的正则，然后还要往外层继续找。它不挡自己里面的正则。
