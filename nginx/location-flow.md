# location 匹配流程图

> 速查图。讲解和实验在 [location 匹配规则](./location.md)。返回 [Nginx](./README.md)。

location 只看请求 URI 的 **path**（不含 host、query）。五种常用写法走同一套顺序：

```text
                    收到请求
                        │
                        ▼
             ┌───────────────────┐
             │ 有没有精确匹配？     │
             │ location = /xxx   │
             └─────────┬─────────┘
                       │
             ┌─────────┴─────────┐
             │                   │
            有                   没有
             │                   │
             ▼                   ▼
          直接使用         在前缀里找最长的
          精确匹配         （普通前缀 和 ^~）
                                 │
                           ┌─────┴─────┐
                           │           │
                     最长的是 ^~     最长的是
                           │       普通前缀
                           │           │
                           ▼           ▼
                        直接使用      按书写顺序
                        这条 ^~      检查正则
                                       │
                              ┌────────┴────────┐
                              │                 │
                            匹配到            都没匹配
                              │                 │
                              ▼                 ▼
                            使用正则       使用刚才找到的
                                            最长前缀
```

对应写法：

| 写法 | 含义 | 在图里的位置 |
| --- | --- | --- |
| `location = /abc` | 和 URI **完全相等** | 最先看，命中就结束 |
| `location /abc/` | 普通前缀，取**最长**的那条 | 没精确匹配时参与比长度 |
| `location ^~ /abc/` | 也是前缀，但若它是最长的，**不再查正则** | 最长前缀带 `^~` 的分支 |
| `location ~ regex` | 大小写敏感正则 | 普通前缀记住之后，从上到下第一条命中 |
| `location ~* regex` | 大小写不敏感正则 | 和 `~` 一起按书写顺序比 |

两条提醒：

- `^~` 只有**自己成为最长前缀**时才跳过正则。更长的普通前缀赢了，仍会去查正则。
- 多条正则都能对上时，用配置文件里**先出现**的那条，不是更「精确」的那条。
